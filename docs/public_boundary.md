# Public Boundary

This repository is designed to be public from the first commit. It must stay domain-neutral and implementation-light.

## Safe To Publish

- generic AI OR contracts;
- agent topology;
- rule-first planning utilities;
- contract validation utilities;
- small public examples;
- narrative documentation;
- release-boundary checks.

## Keep Private

- private vertical applications;
- customer or operator data;
- proprietary solver internals;
- production model-building code;
- business-specific rule libraries;
- generated outputs, traces, logs, archives, and spreadsheets.

## Git History Rule

Public releases must use a fresh Git history. Do not publish a repository that previously contained private implementation material and then removed it in later commits.
